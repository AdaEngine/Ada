# Ada Studio Imported Animation

The bottom Animator has a common skeletal timeline and a node canvas. Model hierarchy and Inspector share its selection. For graph data, use graphInspect on an open loaded GLB/glTF or animlib workspace, then graphApply with its graph revision and a complete detached graph. Graph Undo/Redo shares canvas history. graphPreview requires a valid draft; graphBind applies it to a compatible scene entity with the current scene revision. Keep graph and library revisions separate. Incomplete graphs show diagnostics; malformed IDs and excessive compilation work are rejected before publication. See the AnimationAuthoring guide for budgets and the complete Tool example.

1. Inspect the GLB/glTF for skins, joint counts, exact case-sensitive clip names, durations and interpolation modes. Unnamed clips use `Animation <index>`. Use the returned name without inventing Idle/Walk/Run names.
2. Read the current `Model3DSource` component descriptor. For simple playback set `animation`, `autoplay: true` and `repeats` on the authored entity, retaining its source and other fields. Each placed model has an independent runtime player.
If the scene payload already contains `animationGraph`, it takes precedence over the single `animation` clip. Preserve the authored graph; do not silently remove it to force clip playback. Pose-graph editing and skeletal keyframe/rig authoring are different capabilities.

3. Validate before Play. The native importer supports node TRS translation/rotation/scale and morph-weight channels with LINEAR, STEP and CUBICSPLINE interpolation. Extra joint influence sets remain outside this profile. Each skin supports at most 128 joints.
4. Run visible Play, inspect runtime errors, and compare completed captures at different times. A clip existing in the file is not proof it plays. The isolated logic simulation does not install the Model3D plugin and cannot verify skeletal playback.

For a frozen pose, check the selected name, autoplay, Play state and missing model/clip errors. For deformation, investigate joint order, inverse bind matrices, rest transforms and vertex weights. Imported asset bounds reported by inspection are rest-pose bounds, not animated bounds. Do not decimate a character as a static prop or discard its skeleton to solve a rendering issue.

For editable clips, read the offline `AnimationAuthoring` guide. Native desktop hosts provide `editor.animation.<action>` with a bounded `requestJSON` containing `AnimationAuthoringRequest`. Inspect a library for revisions/IDs, or extract a case-sensitive source clip from a project GLB/glTF into `Assets/...animlib`. Create starts from rest; capture samples an existing clip. Apply atomic `AnimationEdit` batches with `expectedRevision`; replace keys explicitly. The UI, agent and API 2 project Tools share drafts and Undo history. Save is explicit. Bind requires a saved compatible library, open scene revision and Model3DSource entity; it preserves an existing graph. Use qualified runtime names from inspection in graph clip nodes. Reload/Discard recover conflicts only with explicit discard consent. Source model bytes remain unchanged.

For 3D IK, discover `editor.animation.modifierInspect/Create/Apply/Sample/Save/Undo/Redo/Preview/Bind/Reload/Discard`. These use the same bounded request envelope and shared draft/history as the Modifiers panel. A saved `.animmod` contains a complete rig binding and an ordered two-bone/FABRIK stack. Use exact bone IDs and directly parented chains; two-bone needs three joints. Targets/poles in the resource are model-space points. Scene binding uses saved resources, both resource and scene revisions, and optional stable marker entity IDs plus local offsets. Markers must be outside every animated rig subtree. Rigid positive-uniform transforms are supported; unsupported transforms or missing markers skip the affected modifier with diagnostics. Read AnimationIK and AnimationAuthoring before editing. The real API 2 IKHelper Tool example demonstrates the same service and explicit saving.

Native temporal curves use key `curve` metadata through the same revisioned `key.put` operation. `easing` contains `family` (linear/quadratic/cubic/quartic/quintic/sine/exponential/circular/back/elastic/bounce), `direction` (in/out/inOut/outIn) and optional bounded overshoot/amplitude/period. Translation, scale and morph tracks also support `bezier` interpolation with per-component `incoming`/`outgoing` arrays of `{timeOffset, valueOffset}` in seconds/value units. These are distinct from raw cubic key derivatives. Rotation tracks reject scalar Bézier handles. Native curve edits promote `.animlib` to schema 2; inspect key pages and preserve their metadata when updating keys. Each library permits 500,000 compiled native scalar segments; large operations remain subject to request/key/byte limits.

CPU sample/validation responses do not prove rendering. Request the library or modifier preview, wait for load, capture it, then verify visible Play. Native rig creation, automatic skin inference, retargeting, additional tangent modes/canvas handle dragging, state machines, native 2D spline deformation and native 2D IK remain later/separate capabilities. Discover host tool availability before using animation actions on a mobile/cloud host.

For new procedural assets, load `ada-procedural-models`: `editor.model.generate` accepts explicitly placed joints, rigid/two-joint weights and linear joint translation/rotation clips from interpreted AdaScript. Geometry and rig rules are authored together in that recipe; importing a model does not expose it as editable generator geometry.
