# NumberInput для AdaUI и AdaEditor

Статус: предложение к реализации, 9 октября 2026 года. Все новые имена API
и правила взаимодействия ниже — проектный контракт.

`NumberInput` объединяет точный ввод числа с клавиатуры, изменение на заданный
шаг и scrubbing — изменение значения горизонтальным перетаскиванием.
Компонент нужен прежде всего в Inspector: для координат, размеров, параметров
материалов, света, физики и анимации. Общий контрол принадлежит AdaUI;
оформление Inspector и интеграция с историей документов принадлежат AdaEditor.

Референс: приложенное `number_input.mp4` и описание `FeathersNumberInput`.
Из референса берём сочетание текстового ввода и перетаскивания, отдельные
жёсткие и мягкие границы, настройку точности и шагов. Конкретные жесты,
обработка ошибок, API и Undo ниже определяют предлагаемое поведение AdaUI.

## Что уже есть

В AdaUI есть [TextField](../../Sources/AdaUI/DSL/TextField.swift) с
`Binding<String>` и `onSubmit`. В
[Inspector](../Sources/AdaEditor/UI/Editor/EditorInspectorSidebar.swift)
редактируемые скалярные поля без специализированного контрола попадают в
`editorTextField`; координаты векторов также используют текстовые поля.
[Поля графа анимации](../Sources/AdaEditor/UI/Editor/EditorAnimationGraphEditor.swift)
хранят отдельный текстовый черновик и обновляют число при успешном разборе.

[EditorComponentField](../Sources/AdaEditor/EditorComponentRegistry.swift)
уже различает числовые виды полей и содержит `minimumValue`.
Для нового контрола потребуется согласованная конфигурация обеих границ,
мягкого диапазона, шага и точности. Существующие ограничения полей нужно
сохранить при миграции.

## Вид и взаимодействие

В покое поле показывает число и, при необходимости, единицу измерения.
Подпись свойства остаётся снаружи. Для вектора используются независимые
поля X/Y/Z/W с существующими цветами осей. Единица измерения — отдельный
визуальный суффикс, она не входит в редактируемую строку.

| Действие | Результат |
| --- | --- |
| Клик по числу без перемещения | Текстовый режим, число выделено целиком |
| Перетаскивание по неактивному полю | После порога 4 логических точки начинается scrubbing |
| Перетаскивание по тексту в текстовом режиме | Обычное выделение текста |
| Enter в текстовом режиме | Подтверждение ввода |
| Escape | Отмена текущего ввода или перетаскивания |
| Tab / Shift+Tab | Подтверждение корректного ввода и переход фокуса |
| Стрелки ↑ / ↓ при фокусе | Увеличение / уменьшение на `step` |
| Кнопки − / +, если включены | Изменение на `step` |
| Shift при scrubbing или шаговом изменении | Точный режим: множитель 0.1 |
| Alt / Option при scrubbing или шаговом изменении | Быстрый режим: множитель 10 |

Если оба модификатора нажаты одновременно, приоритет у точного режима.
Модификаторы не меняют арифметику вручную введённого числа. В целочисленном
поле минимальный эффективный шаг равен 1.

При наведении на доступную для scrubbing область используется горизонтальный
курсор изменения размера; в текстовом режиме — текстовый курсор. Поле имеет
различимые состояния hover, focus, drag, error и disabled. Шаговые кнопки
опциональны; если включены, их место резервируется, чтобы число не сдвигалось
при наведении. На соответствующей жёсткой границе кнопка отключается.

Колесо мыши в первой версии прокручивает Inspector. Scrubbing не требует
бесконечного перемещения или системного переноса курсора.

## Жёсткие и мягкие границы

**Hard limits** задают допустимые значения, которые контрол может записать
через binding. Они действуют при текстовом вводе, вставке, scrubbing,
клавиатурных шагах и нажатии кнопок. Границы включительные; каждую сторону
можно не задавать. При подтверждении корректное число за пределами диапазона
ограничивается ближайшей границей, и поле показывает полученное значение.

**Soft limits** задают рабочий диапазон только для scrubbing. Они позволяют
быстро подбирать обычные значения, сохраняя возможность вручную ввести
большее или меньшее число. Клавиатурные шаги и кнопки используют hard limits.
Если мягкая сторона не задана, на этой стороне действует только hard limit.

Пример: интенсивность света имеет hard range `0…100`, soft range `0…10`.
Из значения `5` можно дотянуть до `10`; вручную можно ввести `25`.
Ввод `150` подтверждается как `100`.

### Scrubbing из значения вне мягкого диапазона

Число, введённое за мягкой границей, не должно прыгать к этой границе в начале
жеста. Предлагается направленное ограничение:

- Из `25` при soft maximum `10` движение вправо не увеличивает значение.
  Движение влево уменьшает его постепенно: `25 → 24 → 23 → … → 10`.
- После входа в мягкий диапазон дальнейший scrubbing остаётся внутри него.
- Для значения ниже soft minimum действует симметричное правило.
- Hard limits действуют на каждом обновлении, включая движение вне soft range.

Конфигурация валидна, если обе пары границ упорядочены, soft range находится
внутри hard range, а все заданные числа конечны и представимы в типе значения.
Пустой диапазон допустим: одинаковые границы фиксируют одно значение.
Ошибочная конфигурация должна выдавать диагностику и отключать изменение,
не приводя к падению и не переставляя границы молча.

Внешняя модель отвечает за собственную валидацию: UI-контрол не защищает
запись из скрипта, загрузчика сцены или другого API. Некорректное внешнее
значение показывается как ошибка и не исправляется побочным эффектом отрисовки.
Для конечного значения вне hard range следующий успешный ввод нормализует
результат; для NaN/Infinity scrubbing и шаги недоступны, но текстовый ввод
позволяет восстановить корректное число.

## Шаг, чувствительность и точность

Эти настройки имеют разное назначение:

| Настройка | Назначение | Предлагаемое значение по умолчанию |
| --- | --- | --- |
| `step` | Прибавка для кнопок и стрелок | 1 |
| `dragStep` | Прибавка за одну логическую точку горизонтального движения | 0.01 для Float/Double, 1 для Int |
| `fractionDigits` | Максимум знаков после разделителя в покое | 3 для Float/Double, 0 для Int |
| `valuePrecision` | Округление записываемого значения до заданного числа десятичных знаков | Отсутствует |
| `showsStepper` | Показ кнопок − / + | false |

`step` и `dragStep` должны быть положительными и конечными. Для `Int` задаются
целые шаги; коэффициенты модификаторов сохраняют целочисленный результат.
Переполнение ограничивается границей типа до записи в binding.

В обычном режиме при движении на `dx` значение меняется на `dx × dragStep`.
Точный и быстрый режимы умножают эту прибавку на свой коэффициент. Расчёт
хранит накопленное смещение с достаточной точностью: частые маленькие события
не должны теряться после округления. Изменение модификатора во время жеста
меняет чувствительность последующего движения без скачка значения.

После упора в границу движение обратно сразу меняет число. Избыточное
смещение за границей не накапливается как расстояние, которое нужно «отмотать».

`fractionDigits` влияет только на отображение: показ `1.235` не должен
перезаписывать значение `1.23456`. При входе в текстовый режим используется
представление, которое позволяет сохранить исходное число без потери точности;
подтверждение без изменения не меняет модель.

Если задан `valuePrecision`, новые значения округляются до указанного числа
десятичных знаков; половины округляются от нуля. Затем применяются hard limits
и ограничения направления scrubbing. Граница имеет приоритет над округлением:
для максимума `0.995` допустимо сохранить `0.995` даже при precision `2`.
Шаг меньше кванта точности отклоняется как некорректная конфигурация, если
не способен изменить представимое значение. Для Int точность фиксирована на 0.

Форматирование убирает лишние конечные нули и отображает отрицательный ноль
как `0`. Округление для вывода никогда не участвует в арифметике жеста.

## Текстовый ввод и ошибки

Текстовый черновик хранится отдельно от числового binding. Промежуточные
строки `""`, `"-"`, `"."`, `"0."` не превращаются автоматически в ноль
и не меняют модель. В первой версии текст обновляет число при подтверждении;
scrubbing обновляет его непрерывно для предпросмотра сцены.

Разбор принимает знак, десятичное число и экспоненциальную запись для
Float/Double. Принимаются точка и десятичный разделитель текущей локали;
разделители групп разрядов и строки с неоднозначным сочетанием разделителей
отклоняются. Вставка использует те же правила. Для Int дробная и
экспоненциальная запись отклоняются; большие целые не проходят через Double.
Формулы и автоматическое преобразование единиц в первую версию не входят.

При Enter с некорректной строкой поле остаётся в текстовом режиме и показывает
ошибку; binding сохраняет прежнее значение. При уходе фокуса или Tab
некорректный черновик отменяется, отображается последнее значение модели,
фокус продолжает переход. Escape отменяет черновик без сообщения об ошибке.
NaN, Infinity и переполнение при разборе всегда считаются ошибкой.

## Жизненный цикл изменения и Undo

Контрол сообщает начало взаимодействия и его завершение. Запись в binding
сообщает промежуточное значение; итог завершения различает `committed`,
`cancelled` и `interrupted`.

- Scrubbing: начало после порога движения, промежуточные записи во время
  жеста, подтверждение при отпускании указателя.
- Текст: начало при входе в редактирование, одна запись при успешном
  подтверждении, завершение после подтверждения или отмены.
- Кнопка или одиночное нажатие стрелки: одна завершённая операция.
  Автоповтор удерживаемой клавиши группируется до её отпускания.
- Escape во время scrubbing восстанавливает значение начала жеста и
  завершает операцию как `cancelled`.
- Потеря захвата указателя или деактивация окна отменяет scrubbing.
- Смена документа, выбранной сущности или внешнее изменение binding
  прерывает взаимодействие как `interrupted`: старая операция не должна
  перезаписать новый внешний результат.

AdaEditor сохраняет один снимок до операции, показывает промежуточные
изменения сцены и записывает один итоговый шаг истории. Отмена и операция
без изменения итогового значения не создают шаг Undo. После interrupted
старый снимок не применяется к новому документу или внешней ревизии.

Текущий [EditorDocumentHistory](../Sources/AdaEditor/UI/Editor/EditorDocumentHistory.swift)
записывает снимки отдельных изменений; для scrubbing потребуется группировка
транзакции. Нельзя просто отправлять каждое движение в существующий путь
записи истории. Постоянный компонент AdaUI не должен зависеть от типов
документов, сущностей или истории AdaEditor.

## Предлагаемый Swift API

Эскиз API, а не пример, доступный в текущем пакете. `NumberInput<Value>`
и типизированная конфигурация поддерживают `Int`, `Float` и `Double`.
Числовая семантика для Int сохраняется без промежуточной конверсии в Double.

```swift
@State private var intensity: Double = 5

NumberInput(
    "Intensity",
    value: $intensity,
    configuration: NumberInputConfiguration<Double>(
        hardMinimum: 0,
        hardMaximum: 100,
        softMinimum: 0,
        softMaximum: 10,
        step: 0.1,
        dragStep: 0.01,
        fractionDigits: 3,
        valuePrecision: nil,
        showsStepper: true
    ),
    onEditingBegan: { /* Begin editor transaction. */ },
    onEditingEnded: { outcome in /* Commit, cancel or interrupt. */ }
)
```

Конфигурация — value type; изменяемое состояние ввода и жеста принадлежит
runtime-узлу контрола и сохраняется при обычной перестройке View.
Стиль задаёт внешний вид, сохраняя одинаковую числовую семантику.
Подпись используется и для accessibility; суффикс единицы можно добавить
в стиль или редакторскую обёртку.

## Интеграция в Inspector

Первый этап — скалярные поля `.int` / `.float` и отдельные оси векторов
Transform. Затем тот же контрол можно использовать для света, материалов,
физики и анимации. Переход отдельных панелей не должен менять правила
сериализации сцен или автоматически ограничивать ранее сохранённые значения.

Предлагаемые настройки для первых сценариев:

| Свойство | Hard limits | Soft limits | step / dragStep | fractionDigits |
| --- | --- | --- | --- | --- |
| Position X/Y/Z | Без дополнительных границ | Без дополнительных границ | 1 / 0.1 | 3 |
| Rotation в градусах | Без дополнительных границ | −180…180 | 1 / 0.5 | 2 |
| Интенсивность света, пример | 0…100 | 0…10 | 0.1 / 0.01 | 3 |
| Roughness / Metallic | 0…1 | 0…1 | 0.01 / 0.005 | 3 |
| Количество элементов, Int | 0…10000 | 0…100 | 1 / 1 | 0 |

Это UX-пресеты. Ограничения конкретного компонента имеют приоритет;
значения таблицы не устанавливают новых требований движка.
Углы не нормализуются по модулю 360 автоматически. Для Scale не вводится
универсальная положительная нижняя граница: допустимость отрицательных
значений определяется компонентом.

Метаданные числового поля нужно передавать через дескриптор, а не определять
по тексту подписи. Текущий `minimumValue` переносится в hard minimum.
Readonly-поля не получают жестов и шаговых действий.

## Платформы и доступность

Общий контрол реализуется в AdaUI без зависимости от SwiftUI/AppKit/UIKit.
Первая интеграция — desktop Inspector. Мышь и клавиатура должны проходить
через штатные маршруты событий и фокуса AdaUI.

На touch-устройствах тап открывает текстовый ввод; scrubbing начинается
только из явной зоны или после удержания, чтобы не захватывать вертикальную
прокрутку. Это отдельный этап проверки, а не обещание мобильного паритета.
Клавиатурные и accessibility-действия увеличения/уменьшения обеспечивают
альтернативу перетаскиванию. Озвучиваются подпись, значение, единица,
ошибка и жёсткие границы. Цвет оси дополняется буквой X/Y/Z/W.

## Критерии приёмки

1. Клик открывает текстовый ввод; движение ниже порога не меняет число.
   Выделение текста в активном поле не запускает scrubbing.
2. Ввод `25` при hard `0…100`, soft `0…10` сохраняет `25`; ввод `150`
   сохраняет `100`. Кнопки и стрелки могут выйти за soft range, но не за hard.
3. Scrubbing из `5` упирается в `10`. Из `25` движение вправо не меняет число,
   движение влево уменьшает его без начального скачка; возврат от границы
   реагирует сразу.
4. Скорость не зависит от частоты событий и физического масштаба экрана.
   Изменение Shift/Alt во время жеста не вызывает скачок.
5. `-`, `0.`, некорректная вставка и переполнение не меняют binding.
   Enter, Tab, потеря фокуса и Escape выполняют описанные правила.
6. Настройка отображения не округляет модель; неизменённый текстовый ввод
   сохраняет точное число. Int не теряет точность выше `2^53` на 64-битной платформе.
7. Один жест с множеством обновлений создаёт один шаг Undo и один Redo.
   Escape восстанавливает начало; возврат к исходному значению не создаёт Undo.
8. Смена выбранного объекта, внешняя ревизия и закрытие документа во время
   изменения не записывают старое значение в новый объект.
9. Сохранение и повторное открытие сцены сохраняют итоговое число;
   Play использует это же значение. Локальный черновик поля не сериализуется.
10. Узкий Inspector, светлая/тёмная тема и масштаб экрана не обрезают
    значение и кнопки. Disabled/readonly и ошибки конфигурации не меняют модель.

Числовые правила проверяются Swift Testing в AdaUI; реальный маршрут
событий — тестами runtime-узла; история, дескрипторы и сохранение — тестами
AdaEditor. Перед выпуском необходима видимая проверка Inspector с мышью
и клавиатурой. Для последующей touch-интеграции отдельно проверяются
запуск в Simulator, ввод и конфликт с прокруткой.
