# Interactive path tracing light transport

Status: accepted by explicit human approval in the contributor conversation on 2026-11-25. Classification: improvement to the existing `PathTracing3D` renderer.

Related designs include [hardware traversal](hardware-path-tracing.md), [path-tracing denoising](path-tracing-denoising.md), and the earlier [interactive-quality proposal](path-tracing-interactive-quality.md). This proposal develops the earlier direct-light sampling idea and builds on the hybrid first hit and denoising paths that have since landed.

## Scope and current behavior

Add a Solari-inspired interactive mode to `Environment3D.pathTracing`. It has a fixed per-interaction light sampling budget, an optional world-space radiance cache for diffuse transport, and improved data for the existing DLSS Ray Reconstruction integration. The existing tracer already supports a raster G-buffer first hit, a software BVH, hardware ray queries on SAGA Vulkan, a portable denoiser, and an exhaustive analytic-light loop. It currently picks up emission when a continuation ray hits an emissive surface. The interactive mode targets dynamic scenes with many lights or small emissive surfaces.

The proposal uses the existing scene extraction, packed geometry tables, material evaluation, acceleration-structure ownership, render graph, and denoiser selection. AdaCorePipelines owns transport and per-view cache state. AdaRender owns backend resource bindings and the existing bridge owns NGX evaluation. The baseline for algorithms is Bevy's [`bevy_solari` at `76295a0d2`](https://github.com/bevyengine/bevy/tree/76295a0d2/crates/bevy_solari/src). Reuse the ideas with AdaEngine's coordinates, material rules and resource layout. Attribute any source-derived code and retain its applicable license notices.

## Behavior

### Transport selection and hit resolution

- Add an opt-in interactive transport setting. Older serialized cameras decode to the current transport. The current transport remains selectable for image comparisons and plain accumulation. The interactive mode can run uncached for diagnosis, for portable execution, and as the fallback when cache resources cannot be used. Report the actual transport, traversal and cache path independently in `Render3DPathTracingStatistics`.
- Keep the raster first hit as the normal entry for supported views and the camera-ray path for views that need it. Both yield the same surface inputs for lighting. The G-buffer remains authoritative for visible geometry when a scene uses separate tracing proxies.
- Give closest-hit and shadow visibility queries a common candidate policy. Share hit semantics between fragment and compute shaders and between the shader BVH and Vulkan ray queries. The closest-hit record identifies the position along the ray, surface or triangle, barycentrics where present, and geometric and shading normals after material resolution. A shadow query stops once it finds an accepted blocker and uses the light distance as an upper bound. Preserve material sidedness, alpha cutoff, stochastic coverage, shadow participation, ray bias and visibility masks. Match the established shadow and continuation behavior on terrain, background, proxies and deformed geometry.

### Direct-light selection

- Add an emitter table backed by the existing analytic-light and traced-geometry inputs. Include authored directional, point and spot lights and sampleable emissive triangles. Keep source identity stable across incremental updates for reproducible sampling and cache invalidation. Bound table memory and give eligible emitters nonzero sampling probability. Resolve emission and PDFs using the sampled point and material. Continue evaluating sky/environment radiance on a path miss.
- Draw a small fixed number of light candidates at each interaction and choose one with resampled importance sampling (RIS), using estimated contribution and proposal probability. Trace the selected candidate's visibility once. Use multiple importance sampling (MIS) to combine direct emissive sampling with BSDF-sampled emissive hits. Maintain the one-light and empty-light cases, avoid zero or invalid PDFs, and keep existing surface emission visible. Start with candidate budgets of eight on the first surface and four on later surfaces. Tune them only against the same unfiltered and denoised benchmark scenes.
- Use the exhaustive path as the compatibility default and comparison baseline for analytic lights. Use a high-sample, uncached reference with matching emission and materials for emissive comparisons. A separate image-space ReSTIR decision can use the measurements from this bounded sampler and cache.

### World-space radiance cache

- Own one bounded GPU cache per traced view. Hash quantized world position, geometric normal and spatial level, verify the complete cell identity before use, and vary cell size with distance from the view. Store a temporally filtered estimate of incoming diffuse lighting and the metadata needed for validation and expiry. Begin with a provisional 16 MiB per-view cap for cache-specific allocations, including update queues and scratch. Overflow drops or bypasses requests. Keep history in world space through normal camera motion.
- Update a bounded number of cells per frame. Read the last valid cell state when estimating direct light and a diffuse secondary bounce for the update. Blend new results using sample age and lighting change. Use ordered GPU passes and disjoint read/write state where required so a lookup never sees a half-published entry. Invalidate incompatible scene, material, light or environment revisions and retire resources when the view goes away. During dynamic movement, conservatively invalidate affected entries or the whole cache when affected regions cannot be identified. Keep the uncached estimator usable while cells warm up.
- Terminate suitable broad-lobe paths into validated cells and multiply the cached estimate by the hit's diffuse response. Trace through sharp reflection paths while the interaction budget permits. Bypass the cache for short segments that can cross an occluder within a cell, incompatible revisions, cold entries and rejected lookups. Report cache hits, misses and update counts in opt-in diagnostics without synchronizing the CPU for each frame.
- First enable cache updates on validated SAGA Vulkan devices. The current AdaRender compute interface exposes textures and uniforms, while the pinned SAGA Vulkan backend can dispatch compute with acceleration structures. Establish storage-buffer and acceleration-structure binding, ordering, and resource lifetime in a focused backend test. Retain the existing fragment traversal for portable uncached execution. A fixed-budget compute dispatch is sufficient for the first version. Profile active-cell compaction and indirect dispatch before introducing them. The same applies to batching shared light candidates and moving the full pixel tracer to compute.

### DLSS Ray Reconstruction

- Keep the current RR selection and portable fallback. RR continues to receive fresh noisy HDR at DLSS input resolution and owns image-space accumulation. The world cache is upstream of both denoisers. Keep raster depth, motion, and the existing material guides available as the fallback and for other consumers.
- Compare the current raster guides with Solari's view-dependent specular albedo, background inputs, and specular path data. Improve the material guides where the RR input contract supports them. Record first specular hit distance from a continuation ray and pass it through the existing NGX bridge where the pinned Vulkan input supports it. Define valid, miss and unavailable data for each guide so the bridge can omit an unsupported input.
- Evaluate reflected motion and Primary Surface Replacement (PSR) as a separate RR-only step after measuring the basic guide improvements. PSR describes a reliable near-perfect planar reflection using attributes of the reflected surface, including motion from previous transforms when available. Keep these overrides in RR inputs; preserve the original depth and motion for ordinary rendering and portable filtering. Use the existing RR guides when the reflection is rough, the data is missing, or reprojection is unreliable. Require a paired moving-mirror comparison before enabling PSR by default.

## Delivery sequence

1. Record baseline images, convergence, GPU timings and ray counts. Extract common hit and visibility tests before changing the estimator.
2. Ship the opt-in light sampler, including emissive geometry, and validate the uncached path on software BVH and Vulkan ray queries.
3. Validate the SAGA compute binding and synchronization prerequisites. Add, measure and validate the bounded radiance cache with uncached fallback.
4. Validate RR guide changes on compatible hardware using the existing NGX integration. Measure reflected motion and PSR against the simpler guide version.

## Acceptance and documentation

- Exercise real ray traversal and render paths. Cover closest hit versus an early accepted shadow hit, finite ray distance, alpha-cutout blockers, back faces, a non-shadow-casting mesh, raster/tracer proxies and software/hardware comparison. Use rendered fixtures with a fixed seed where meaningful. Compare stochastic coverage statistically where traversal order differs.
- Render no-light and one-light fixtures, a many-light fixture, and a tiny emissive area-light fixture. Compare finite HDR output and sample-averaged brightness against the corresponding uncached reference. Show that visibility-ray work is bounded as analytic light count increases. Use the same scene, resolution, ray budget and camera route for GPU timing and convergence captures. Report results separately for a simple scene and a many-light scene.
- Exercise a cold and warmed cache, camera translation, a moving light and moving occluder, a thin occluder between adjacent surfaces, deliberate cache pressure, and a backend or shader that cannot provide the cache path. Check output against uncached tracing for leakage and stale light. Measure GPU time, hit rate and allocation size with the cache on and off.
- Compare portable and RR outputs with the same transport. On a supported NVIDIA device verify that RR actually encoded and that optional guides were accepted. Capture a static roughness ramp and a moving mirror with off-screen geometry, comparing each guide change independently. Run the contribution checks and the SAGA GPU validation on the affected backends. Record unavailable device checks explicitly before independent review.
