# Meshlets P0 baseline и аудит подготовки

- Дата: 2026-11-02.
- План: [Meshlets preparation, P0](../Plans/2026-11-02-MeshletsPreparation.md).
- Дизайн: [ADR-0028](../ArchitectureDecisions/0028-meshlets-and-portable-cluster-culling.md).
- База исходников: `a7f0ce13`; рабочая копия содержит отдельные пользовательские изменения Editor/AdaUI/AdaText. P0 меняет benchmark fixtures, отчётность и документацию, production renderer не оптимизирует.

## Воспроизводимые нагрузки

Новый opt-in `Render3DGPUTests/MeshletBaseline` выполняет настоящий offscreen renderer, extraction, CPU coarse visibility/LOD/batching, optional GPU Hi-Z и readback контрольных pixels. Builder/culling мешлетов здесь ещё отсутствуют.

| Workload | Геометрия и камера | Назначение |
| --- | --- | --- |
| `partial` | Одна сетка 512×512 ячеек, 524288 triangles, размер 40×16; позиция `[32,0,20]`, камера `[0,0,-10]` | Потенциальный singleton target с геометрией за пределами frustum |
| `occluded` | Та же сетка в `[0,0,20]`; отдельная стенка 12×20×0.5 в `[-6,0,4]` | Внутримешевое occlusion при сохранении видимой части большого draw |
| `allVisible` | Сетка в `[0,0,20]`, камера `[0,0,-40]` | Цена обработки полностью видимого singleton |
| `instances` | 40×40 spheres, общий mesh/material, 16 segments × 12 rings | Сохранение batching; модель не должна искусственно превращаться в singleton draws |
| `smallParts` | 16×16 отдельных cube buffers, общий материал | Нагрузка с большим количеством маленьких singleton parts |
| `garden` | Импортированные `Courtyard`, `Bench`, `Lantern`, `Pedestal` из fixtures | Production glTF/import/hierarchy контроль на существующих моделях |

Процедурные fixtures — оригинальная геометрия под лицензией репозитория. Garden props созданы репозиторными Blender generators; provenance: [Tools/3DAssets](../../Tools/3DAssets/README.md) и [generate_garden_assets.py](../../Tools/3DAssets/generate_garden_assets.py). Сторонние модели не загружаются. Низкополигональные garden props не заменяют крупную production-сцену; большой плоский synthetic mesh изолирует стоимость geometry и не характеризует типичную пространственную связность игрового ассета.

Все объекты сгруппированы под `Environment`/`Lighting`, neutral parent transforms. Одинаковые static cameras и geometry поддерживают exact pixel comparison Hi-Z off/on. Shadows, SSAO, SSR, AA и skybox отключены в этом harness; существующий effect benchmark отдельно сохраняет контроль с shadows и обычной PBR-сеткой.

## Методика измерения

Для каждой нагрузки выполняются три пары Hi-Z off/on; порядок каждой следующей пары меняется. Все samples сохраняются, минимальный round не выбирается. Warmup — 60 кадров на режим, измерение — 90 кадров на round, по умолчанию 1280×720. Проверка pixel equivalence и image readback выполняются **после** окна timing.

Throughput дожидается GPU completion на той же device queue после каждого submission window. На Metal окно ограничено `maxFramesInFlight` (сейчас 3) из-за direct writes в shared memory. На native WebGPU окно составляет до 90 кадров: uploads идут через queue.writeBuffer, а GPU work последовательно использует ring resources в одной очереди. Это throughput-протокол с большей queue latency, не симуляция презентации с тремя кадрами в полёте. Обычный native completion handler с ProcessEvents pump сохраняется; более длинное окно амортизирует его Windows timer granularity. Production queue path не меняется.

Итоговый wall time включает drain, но не копирование текстуры. Raw samples содержат CPU-side app-update wall time и среднее время кадра каждого завершённого окна. Median/p95 по окнам **не являются** индивидуальными frame-latency percentiles; они пригодны только для сравнения того же протокола и window size.

CPU extraction измеряется отдельно через production `RenderWorldExctractor`; list preparation — через `VisibleMesh3DLists.prepare` с текущими source/projection/settings. List wall time включает upload submission. Дополнительно `RenderGraphDiagnostics` измеряет wall time `Main3DRenderNode` (prepare + encode + submission, без profiling waits) в отдельной фазе. По три первых диагностических samples отбрасываются для прогрева локальных caches. Exclusive CPU encode time не инструментирован и не подменяется app-update или main-node time.

Отдельная serialized profiling phase собирает `Render3DPerformanceMetrics`: на Metal доступны pass GPU timestamps, на текущем WebGPU — нет. Эти 12 кадров и diagnostic phase не входят в throughput. Публикуемые census берутся после coarse culling/LOD/batching **до** GPU Hi-Z: это не фактическое число triangles, прошедших GPU occlusion.

Чтобы различить влияние geometry и fill, повторять `partial` при 128 subdivisions и при 640×360 с 512 subdivisions. Вид и projected coverage сохраняются, кроме дискретизации экрана; уменьшение плотности сетки не меняет её плоскую поверхность. По одному уменьшению wall time нельзя объявить сцену geometry-bound без GPU profiling.

## Аудит integration contracts

| Область | Найдено в production source | Требование к следующим срезам |
| --- | --- | --- |
| Coarse visibility и batching | `VisibleMesh3DLists.prepare` выбирает mesh LOD до part batching, ключ включает vertex/index buffer identity и material; повторяющиеся opaque parts объединяются | Eligibility вычислять после batching; не дробить shared instances ради мешлетов |
| Instance addressing | `Model3DDrawPass` slot 3 offset берётся из `batchRange`, `GPUVisibility3DState` может заменить общий instance buffer | Geometry override должен сохранять per-item источник instances; fallback восстанавливает всю связку |
| Topology | `GLTFImportResult.Primitive.convertTopology` разворачивает fan в list, но strip оставляет `.triangleStrip`; missing indices заменяются последовательными indices | V1 принимает уже нормализованный triangle list; strip пока fallback. Его разворачивание требует общего helper/тестов, а не предположения о текущем importer |
| External buffers | `NativeGLTFLoader.loadBuffers` загружает `.bin` относительно resource base URL, также поддерживает GLB/data URI | Sidecar digest должен учитывать dependency bytes и import version/options |
| Asset roots/cache | `AssetsManager` различает `@res://`, `@cache://`, project virtual roots и loadFresh; sidecar format/generation lifecycle ещё не существует | Чтение source/sidecar через один resolver, checked version/hash, atomic generation install; filesystem cache paths не включать в проекты |
| Export | Web exporter копирует resource bundles/manifest и директорию `Assets`; неизвестный derived resource автоматически не генерируется | При P1/M3 выбрать manifest entry и sidecar delivery; cache-only output не считается экспортируемым ассетом |
| WebGPU source indices | `createIndexBuffer` использует только `INDEX | COPY_DST` | Не читать этот buffer как storage; compute-readable cluster source и writable `STORAGE | INDEX` output создаёт отдельный processor |
| WebGPU ring | `WGPUVisibilityProcessor` выбирает slot по modulo, upload через queue.writeBuffer; GPU writes/reads идут через ordered queue submissions | Для новых resources явно зафиксировать queue order и retirement; не объявлять modulo доказательством lifetime |
| Metal ring | `MetalVisibilityProcessor` выбирает slot по modulo и пишет MTL shared memory через `contents().copyMemory` | До native meshlet path нужен completion-controlled reuse; в проверенном offscreen пути явного глобального in-flight limiter не найдено. Ограничение drawable count относится к window surfaces |
| Completion API | Native `WGPUCommandEncoder` регистрирует work-done callback и pump; WASM вызывает handlers сразу после submit | Browser handler не является GPU completion fence. Нужен корректный browser resource reuse contract до M12 |
| Shader stages | Общий shader compiler содержит vertex/fragment/compute, mesh/object API не реализован | Mesh shaders не добавлять в рамках CPU foundation/P0 |

Это статический аудит конкретных точек, а не доказательство use-after-free в существующем приложении. P0 harness использует конечное submission window и явный drain; native WebGPU reuse проверяется при очереди длиннее ring, Metal остаётся ограничен ring size. Metal и browser submission требуют собственных runtime stress tests.

## Начальные бюджеты и gates

Для дальнейшего prototype: incremental static meshlet data до 64 MiB на устройство; transient output/scan/arguments до 32 MiB на view **с учётом всех ring slots**; суммарный incremental meshlet budget до 128 MiB на устройство. Это начальные ограничения, не измеренное выделение memory. Раздельно учитывать реально выделенный prepass/Hi-Z и device storage/dispatch limits; shared существующая pyramid не учитывается второй раз.

Один synthetic target из 524288 triangles требует не более 6 MiB `UInt32` compacted indices на slot, 18 MiB на ring из трёх slots, до добавления scratch/metadata. Это позволяет исследовать P1/P2 без неограниченного per-instance умножения памяти. Две камеры и worst-case limits должны проверяться в реализации.

Пороги rollout сохраняются из ADR: ≥10% выигрыша median frame time на целевой сцене; ≤3% median и ≤5% p95 регрессии на controls; память в budget. Window p95 этого отчёта не закрывает настоящий frame-latency gate. Перед rollout нужны обычный frame-loop capture и отдельно Metal GPU evidence.

## Воспроизведение

На Windows focused package позволяет обойти сборку посторонних command plugins. Scratch принадлежит этой задаче; shared `.build` не изменяется. Из корня репозитория:

```powershell
python script/webgpu_validation_package.py .build-codex/meshlets-p0/validation-package
$env:ADAENGINE_WEB_EXPORT = '1'
$env:ADAENGINE_SHADER_SOURCE_ROOT = (Get-Location).Path
$env:TINT_EXECUTABLE = python script/ensure_tint.py
swift build --package-path .build-codex/meshlets-p0/validation-package --scratch-path .build-codex/meshlets-p0 -c release -Xswiftc -enable-testing --product RenderingValidationPackageTests --jobs 12 --disable-sandbox
$env:ADAENGINE_GOLDEN_WEBGPU = '1'
$env:ADAENGINE_MESHLET_BASELINE = '1'
$env:ADAENGINE_MESHLET_BASELINE_OUTPUT = 'D:/Development/AdaEngine/.build-codex/meshlets-p0/evidence'
swift test --package-path .build-codex/meshlets-p0/validation-package --scratch-path .build-codex/meshlets-p0 -c release --skip-build --no-parallel --filter Render3DGPUTests/MeshletBaseline
python script/summarize_meshlet_baseline.py .build-codex/meshlets-p0/evidence/baseline.json
```

Дополнительные env settings: `ADAENGINE_MESHLET_BASELINE_WIDTH`, `_HEIGHT`, `_FRAMES`, `_WARMUP`, `_ROUNDS`, `_SUBDIVISIONS`, `_FILTER` (точное имя workload). Для density/resolution controls использовать отдельные output directories. Старый benchmark запускается с `ADAENGINE_PERF=1`, `ADAENGINE_PERF_FILTER=bare` и filter `Render3DGPUTests/Benchmarks`; его best-of-round summary не смешивается с raw новым протоколом.

На Metal задать `ADAENGINE_GOLDEN_METAL=1`, убрать WebGPU backend selector и использовать root SwiftPM либо focused package. Версия среды, фактический adapter и build log должны сохраняться рядом с результатом. Env flags после работы восстанавливать или запускать в отдельном shell.

## Результаты native Windows

Среда: Ryzen 9 7900X, RTX 4070, driver 610.88 / 32.0.16.1088, Windows 11 Pro 10.0.26300, Swift 6.3.1; Swan `790df787281e9cf1c2358a11bb42b2ec2df01029`, Dawn 148.0.7778.97, D3D12. Desktop workload isolation не обеспечивалась. Версии, source SHA256, параметры и capture hashes сохранены в [manifest.json](../../Evidence/Meshlets/P0-2026-11-02/manifest.json).

Существующий `Benchmarks/effectCostsOnAHeavyScene` прошёл: `bare`, 1920×1080, 400 spheres и shadows, 90 measured frames, best of 3 rounds. Его `free` — 5.25 ms/frame, serialized `wall` — 66.74 ms/frame. Это прежний протокол, включающий финальный readback; значения не сравниваются напрямую с новым harness. [Исходный отчёт](../../Evidence/Meshlets/P0-2026-11-02/existing-benchmark.md).

Новый final-протокол выполнил 54 измерения по 90 кадров: шесть workloads и три controls, по три пары off/on. Все 27 exact pixel comparisons Hi-Z off/on прошли. `partial` дополнительно проверяет выход реального projected corner за clip plane. Геометрия контрольных картинок проверена визуально.

**Вывод:** эти данные не доказывают geometry-bound workload на RTX 4070. Изменение плотности в 64 раза и количества pixels в четыре раза почти не изменило median throughput. CPU app-update median для partial около 0.9 ms; это согласуется с существенным CPU/submission вкладом, но не заменяет GPU profile. У некоторых rounds есть wall outliers до 3–5 ms/frame, поэтому по этому capture нельзя оценивать небольшие проценты выигрыша. Hi-Z также не демонстрирует устойчивого выигрыша на этих controls.

`instances` подтверждает важность сохранения batching; `smallParts` имеет main-node median 1.400 ms при всего 3072 triangles, поэтому дополнительные мелкие draw calls здесь особенно нежелательны. Garden models — полезный importer контроль, но слишком малы для доказательства нужды в мешлетах.

У high-density control один hypothetical compacted output — 24 MiB, ring из трёх slots — минимум 72 MiB. Это превышает начальный per-view budget 32 MiB; такой part пока должен использовать fallback. Увеличивать бюджет только ради synthetic scene этот этап не предлагает.

Проверки:

- Release focused test product собран с `-enable-testing`; root `Package.resolved` не изменён.
- Четыре final запуска `MeshletBaseline` прошли (main + три controls), 4860 measured frames; speed assertions отсутствуют.
- Existing benchmark прошёл отдельно.
- [11 regression tests](../../Evidence/Meshlets/P0-2026-11-02/regression.log) прошли: GPU compaction/indirect pixels, camera motion, occluder removal, resize, frame reuse, visible-list equivalence и timing report. Opt-in `prepareCost` пропущен, не включён в число пройденных.
- `python script/ensure_tint.py --check` прошёл: tool hash и reader/writer smoke. Shader/backend production sources этим срезом не изменялись.

Metal, browser runtime, полная root test matrix, full native WebGPU validation script и exclusive CPU encode time в этом Windows-срезе не проверялись. Для этого benchmark достаточно focused release execution; новая feature не получает статус platform parity.

## Статус P0 и решение

**Реализованы harness, native baseline, census, controls и integration audit. Выходной performance gate P0 остаётся открытым:** подходящий geometry-bound production asset не подтверждён, Metal GPU profile отсутствует. Переход к GPU-оптимизации по одному счётчику triangles не обоснован.

[Intel Sponza 2022 и Sponza + Ivy](MeshletsBenchmarkScene-2026-11-02.md) подключены отдельным следующим срезом: архивы и geometry hashes закреплены, native importer и fixed camera poses проверены, geometry/PBR + Hi-Z baseline и resolution control сняты. 64800 measured frames и 162 exact pixel comparisons прошли, но geometry-bound workload на RTX 4070 по-прежнему не подтверждён. GPU profile остаётся следующим performance-срезом. CPU builder/schema из P1 можно готовить независимо как correctness foundation; runtime GPU rollout остаётся за gate. Current instancing и defaults сохраняются.
