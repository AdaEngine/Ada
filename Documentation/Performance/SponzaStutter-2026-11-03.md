# Задержки кадров Sponza + Ivy

Дата: 2026-11-03. Windows, RTX 4070 12 GiB, Dawn 148 / D3D12, Swift 6.3.1+Asserts.

## Подтверждённая причина

`LocalShadow3DRenderNode.update` определял живые камеры по текущим extracted proxy entities с `Camera` и `GlobalViewUniform`. SceneView может временно не извлечь такую камеру, когда его кольцо публикации занято. Исходная камера при этом остаётся в сцене. Узел ошибочно удалял её atlas, fingerprints граней и uniform caches, затем создавал и рисовал их заново при возобновлении extraction.

Подробный исходный прогон `local-probes` показал 126 медленных выделений local atlas, максимум 202,96 мс. Максимум CPU-узла локальных теней — 249,84 мс. Это происходило и во втором одинаковом повороте камеры; его худший опубликованный кадр занял 273,83 мс. Самое долгое выделение помечено resolution=1024; полный local atlas — 6144×4096 R32F и соответствующий depth/stencil. Это не изменение качества теней пользователем.

Теперь local shadow cache сохраняется по authoritative `ExtractedCameraRenderViewTargets.activeCameraIDs`. Пустой authoritative set по-прежнему удаляет ресурсы действительно удалённых камер. Standalone render worlds без этого ресурса используют прежний query fallback. Тот же lifetime исправлен для scratch uniforms солнечных теней. Движение источников/геометрии продолжает проверяться прежними fingerprints.

## Подготовка демки

Отдельная пауза первого переключения DLSS off занимала около 2,7 с: семь первых компиляций PBR pipeline с другим depth format, примерно по 350 мс. Демка теперь прогревает обычный raster и temporal raster при загрузке. Этапы завершаются по шести реальным публикациям SceneView, а temporal также требует успешных encoded frames. Пользовательские контролы доступны после прогрева и восстановления выбранного режима; ожидание ограничено timeout и поддерживает cancellation.

Для GPU-мешлетов прогревается точный leaf stream с LOD off, затем восстанавливается выбранный hierarchical LOD. Это переносит первую загрузку большого v1 index stream плюща в подготовку. Engine defaults, разрешения текстур/теней, число света и допустимая ошибка LOD не снижены.

## Как измерялось

Опциональный сценарий `ADAENGINE_SPONZA_PROFILE_STUTTER=1` записывает интервалы фактической публикации SceneView, а не обратную величину среднего FPS из внешнего overlay. Размер выхода всех сравнений — 3810×1684, DLSS Quality 2540×1123, 12 локальных источников, высокие тени 80 м, GPU meshlets, LOD 2 px. Flying light и Hi-Z выключены. Для отдельных этапов меняется только соответствующий параметр.

Сценарий: stationary 6 с; два одинаковых поворота по 12 с; перемещение 12 с; LOD off/on и DLSS off/on по 6 с; baseline/high shadows и lights off/on по 4 с. Readback изображений и GPU index counters в измеряемом интервале отсутствует. Снимки graph diagnostics и запись JSON выполняются между интервалами; async App timings, пересекающие эту границу, не трактуются как CPU-время конкретного кадра.

`ADAENGINE_STALL_PROBE=1` включает монотонные slow-operation метки (`ADAENGINE_STALL_THRESHOLD_MS=15` в этих прогонах). Без opt-in метки не выводятся. `WGPU.CompletionLatency` включает доставку callback и не является GPU timestamp. WPR не удалось включить из-за ошибки policy 0xc5585011; ETW-профиль GPU не заявляется.

## Результат финального прогона

5545 интервалов публикации: **0 кадров дольше 200 мс**, 2 кадра дольше 100 мс. Во всех этапах движения камеры и переключения LOD кадров дольше 100 мс не было. Значения ниже — максимум опубликованного интервала, а не GPU timestamp:

| Этап | До, мс (`local-probes`) | После, мс (`final`) |
| --- | ---: | ---: |
| Первый полный поворот | 227,88 | 54,98 |
| Повтор того же поворота | 273,83 | 54,03 |
| Перемещение в галерее | 36,10 | 55,01 |
| LOD off и поворот | 302,85 | 50,83 |
| LOD on и поворот | 224,29 | 54,78 |
| DLSS off | 2707,82 | 103,07 |
| DLSS on | 296,65 | 80,88 |
| Высокие тени после baseline | 123,62 | 103,78 |

P95 при двух поворотах — 18,92 и 18,35 мс; при перемещении — 19,27 мс. Это ограниченный воспроизводимый маршрут, а не гарантия минимального FPS во всей сцене. Худший интервал перемещения вырос, поэтому уменьшение каждого отдельного максимума не заявляется. Первые компиляции перенесены в загрузку, а не устранены как вычислительная работа.

Оставшиеся 103–104 мс возникли по одному разу при отключении DLSS и повышении качества теней. Изменение разрешения требует нового atlas: в финальном прогоне это заняло 30,37 мс; прежние повторные выделения при движении отсутствуют. Дополнительный GPU stall/residency механизм по этим данным не доказан; переделка ownership caches не выполнялась. Во время записи flying light выключен, поэтому результат не описывает стоимость динамических point-light shadow faces.

## Проверки

`script/validate_webgpu.sh`, release, enable-testing, изолированный scratch `.build-codex/meshlets-p0`, native DLSS runtime: **47 tests / 17 suites passed за 31,932 секунды**. Фильтр: `ShadowCacheLifetime|LocalShadowPrecision|Meshlet|DLSS|Temporal3D|WGPUCommandCompletion|TintToolchain|TintShaderCompiler`.

Два новых GPU-теста выделяют настоящие atlas/depth textures. Первый временно убирает extracted Camera/GlobalViewUniform, вызывает production update, проверяет сохранение texture identity, fingerprints и slots, возобновление без redraw; удаление исходной камеры обязано освободить cache. Второй меняет camera pose, temporal input scale и meshlet LOD и проверяет reuse статических граней. Дополнительно выполняются существующие GPU meshlet/temporal/DLSS/precision и fresh Tint проверки. Полный suite всего репозитория и Metal в этом исправлении не запускались.

Компактные summaries и журналы: `Evidence/Meshlets/Stutter-2026-11-03`. Полные исходные интервалы/diagnostics сохранены в task scratch `stutter/*.json`; ранние прогоны `fixed`/`fixed-repeat` предшествуют дополнительному прогреву finest stream и не подменяют финальный результат.
